# Interface Copy

Use words to make the interface easier to understand and operate. Treat each string as part of the interaction, not decoration.

## Perspective and vocabulary

Write from the user's side of the screen. Name objects by what people recognize and control rather than by implementation details. Describe what something does in plain terms instead of selling it.

Give one concept one name throughout the flow. If the action is **Publish**, its confirmation is **Published**, not **Submitted successfully**. Use active voice, sentence case, plain verbs, and specific nouns.

## Controls and guidance

Make controls predict their result:

- **Save changes**, not **Submit**.
- Labels identify; helper text clarifies; examples demonstrate. Give each element one job.
- Put essential guidance before the action that depends on it.
- Tune the register to the audience and brand while preserving clarity.

## Failure, empty, and success states

State what happened and the next available action. Errors should identify the problem precisely and explain how to recover. Empty states should orient the user and offer the relevant first action. Success messages should confirm the completed action without filler.

## Completion check

Review every user-facing string. Each must use the interface's established vocabulary, serve one identifiable purpose, match the resulting action or state, and give enough direction for the user to proceed. Revise any string that fails one of these checks.
